# 2026-10-30: A failed refresh replaced the whole step screen

- **Area:** frontend
- **Author:** Bonvee120 + agent
- **Symptom:** In a click-through of the arrival screens on the real backend, two designed notices never appeared. With the backend stopped, tapping "Start unloading" showed a spinner and then a full-screen "We cannot reach MmiriOma right now. Check your data connection and try again." with "Try again", not the inline "Not sent. Check your connection and try again. Nothing changed." After the dispatcher cancelled a job the driver had open, tapping "I tried to reach the customer" showed a full-screen "Order not found" with "Try again", not "This job was reassigned. It is no longer on your list." with "Back to dashboard".
- **Cause:** Every step action ends with `onSettled: refresh`, which invalidates all partner queries (`queries.ts`). When the refetch of the job (or the profile) failed, TanStack Query kept the cached data but set `isError`. `JobStep` (`if (job.isError)`) and `VehicleGate` in `PartnerArea.tsx` (`if (profile.isError)`) took that as "show the error screen" and removed the step before its own `StepError` could be seen. Fixing `JobStep` alone changed nothing in the browser, because `VehicleGate` then did the same one level up.
- **Fix / workaround:** Both guards now show the full-screen error only when there is no data at all (`isError && data === undefined`). Tests: a failed step plus a failed refresh keeps the screen and shows the notice (network and 404), and a job or profile that never loaded still shows the error screen. Two traps while writing them: a `queryFn` such as `api.getPartnerProfile` is read when the component renders, so a `vi.spyOn` added after the first render never sees the refetch (install it before rendering, letting the first call through); and React Query tells the screen about a failed refetch a tick after `invalidateQueries` resolves, so a check made straight away passes on the broken code. Each test was run against the unfixed code and failed there before it was kept.
- **Status:** resolved
